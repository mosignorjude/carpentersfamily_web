## Local hardening implemented

- The Next.js Proxy creates a fresh cryptographic nonce per request, passes the Content Security Policy into the render request and response, and preserves Supabase session-cookie refresh behavior.
- Production CSP allows scripts/styles with the per-request nonce, denies inline style attributes, limits network connections to the configured Supabase origin and its matching WebSocket origin, denies frames/objects, and upgrades insecure requests. Production does not allow `unsafe-inline` or `unsafe-eval`.
- The small club logos and generated attendance QR use native image elements because Next.js Image adds a CSP-blocked inline style attribute. The 404 page waits for the request so its generated scripts receive the request nonce; neither case weakens the CSP.
- Added one-year HSTS without `includeSubDomains` or preload because a production domain and its subdomain ownership have not been verified. Existing MIME sniffing, framing, referrer, and powered-by protections remain; camera, geolocation, and microphone access are disabled.
- Added a least-privilege GitHub Actions workflow. It pins the checkout and Node setup actions to full commit SHAs, persists no checkout token, has read-only repository permission, uses synthetic loopback Supabase settings, and adds no deploy or database credentials. It runs dependency audit, lint, the complete Node security regression suite, build, and production HTTP header/auth-boundary smoke tests. It does not push migrations or deploy.
- `.env*`, `.vercel`, and `supabase/.temp` remain ignored by `.gitignore`. The local server-only Supabase secret was not found in `.next/static`; a source scan found no matching common secret-token/private-key patterns.
